# S-Cloud — облачный провайдер

КР 1: консольная информационная система на **Java 21**, без Spring и ORM.
Основная сущность — **заявка на облачный ресурс**, связанная с клиентом.
Хранение: **PostgreSQL 17 в Docker**, доступ через JDBC. Экспорт: Apache POI, `.xlsx`.
Программа ведёт учёт заявок; создание реальных ресурсов у внешних провайдеров не выполняется.

## Возможности

| Требование | Реализация |
|---|---|
| Две связанные сущности | `Client` → `ResourceRequest`, связь один ко многим |
| CRUD | Клиенты и заявки: создание, список, ID, изменение, удаление |
| Поиск | Часть названия, часть описания без учёта регистра, ID клиента |
| Фильтры | Статус, тип, регион, их пересечение |
| Сортировка | Дата по возрастанию/убыванию, диск по убыванию, название |
| Статистика | 11 показателей; CPU/RAM/диск учитывают только `PROVISIONED` |
| Excel | Листы «Статистика», «Клиенты», «Заявки», даты/числа, фильтры, закрепление заголовков |
| Таблицы БД | Пункт 7: имена таблиц и содержимое обеих предметных таблиц |
| Обработка ошибок | Неверные числа, ID, enum, бизнес-правила, соединение, SQL, файловые ошибки |
| Циклическое меню | После действия/ошибки возврат в текущее меню, 0 — назад/выход |

Типы ресурсов: `VIRTUAL_MACHINE` — виртуальная машина, `DATABASE` — управляемая БД,
`OBJECT_STORAGE` — объектное хранилище. Регионы: Москва, Санкт-Петербург, Казань.
В меню enum выбираются номером. При изменении параметров вводится полная новая конфигурация.
Удаление требует ввода `ДА`; другие ответы отменяют операцию.

## Бизнес-правила в Java

1. Имя клиента, компания и название заявки обязательны; длины ограничены схемой и сервисом.
2. Email имеет корректную базовую форму, приводится к нижнему регистру и уникален.
3. Клиент заявки должен существовать; ID должен быть положительным.
4. Тип ресурса и регион обязательны и выбираются из enum.
5. Диск — от 10 до 10000 ГБ.
6. Для VM/БД CPU — 1–64 ядра; RAM — не менее 2 ГБ на ядро, максимум 512 ГБ.
7. Для объектного хранилища CPU и RAM равны нулю.
8. Новая заявка всегда создаётся в статусе `NEW`.
9. Разрешены только переходы `NEW → APPROVED/REJECTED/CANCELLED`, `APPROVED → PROVISIONED/CANCELLED`.
10. Изменять параметры и клиента можно только у заявки `NEW`.
11. Удалять заявки `APPROVED` и `PROVISIONED` нельзя.
12. Нельзя удалить клиента, пока у него есть заявки.

Терминальные статусы: `PROVISIONED` (ресурс выделен), `REJECTED` (отказ), `CANCELLED` (отмена).
Повторное присвоение того же статуса также запрещено.
Описание необязательно, максимум 2000 символов. Изменение заявки проверяет `version`:
одновременное сохранение устаревшей версии отклоняется.
Проверки находятся в сервисах, поэтому действуют и при вызове вне консольного меню.
FK, UNIQUE, NOT NULL и CHECK дополнительно защищают данные в PostgreSQL.
