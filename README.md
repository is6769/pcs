# S-Cloud — облачный провайдер

КР 2: настольное приложение **JavaFX 21 / Java 21 / Maven**, без Spring и ORM.
Основная сущность — **заявка на облачный ресурс**, связанная с клиентом.
Хранение: **та же PostgreSQL 17 из КР 1 в Docker**, прямой доступ через JDBC. Экспорт: Apache POI, `.xlsx`.
Программа ведёт учёт заявок; создание реальных ресурсов у внешних провайдеров не выполняется.

## Запуск

Нужны JDK 21, установленный Maven 3.9+ и работающий Docker Desktop (Windows)
либо Docker Engine с Compose (Linux). JavaFX загружается как зависимость Maven;
отдельный JavaFX SDK и демонстрационная система преподавателя не требуются.

Сначала задайте переменные окружения `DB_URL`, `DB_USER` и `DB_PASSWORD`
(см. раздел подключения ниже). Затем из корня проекта:

```powershell
docker compose up -d --wait
mvn clean test
mvn javafx:run
```

Если `JAVA_HOME` не настроен, укажите путь к установленному JDK 21.
В IntelliJ IDEA откройте `pom.xml` как Maven-проект, выберите JDK 21 и запустите цель `javafx:run`.
На Linux/macOS используются те же команды `mvn`.

Второй способ — исполняемый JAR для ОС, на которой выполнена сборка:

```powershell
mvn clean package
.\run.ps1
```

Без аргументов JAR открывает графический интерфейс. `--console` запускает сохранённое меню КР 1,
`--export отчёт.xlsx` выполняет прежний экспорт всей базы из командной строки.

Compose поднимает только PostgreSQL. Приложение запускается на компьютере и подключается к БД через JDBC.
Скрипты `sql/01-schema.sql` и `sql/02-seed.sql` автоматически создают таблицы, 5 клиентов и 10 заявок
при первом запуске **пустого** Docker volume. Существующие данные не очищаются.
Остановка: `docker compose down` (без `-v`, чтобы сохранить данные).

## Подключение к базе КР 1

Настройки подключения задаются вне репозитория:

- `DB_URL` — JDBC-адрес PostgreSQL; для локального Compose: `jdbc:postgresql://localhost:5433/cloud_provider`.
- `DB_USER` — пользователь вашей базы данных.
- `DB_PASSWORD` — пароль этого пользователя.

Задайте эти переменные в окружении терминала или конфигурации запуска IDE.
Все три параметра обязательны; логина и пароля по умолчанию нет.
Прямой запуск Java также поддерживает `-Ddb.url`, `-Ddb.user`, `-Ddb.password` перед `-jar`.
Системные свойства Java имеют приоритет над переменными окружения.
Docker Compose использует те же `DB_USER` и `DB_PASSWORD`. Для него можно скопировать
`.env.example` в локальный `.env` и заполнить пустые значения. Java файл `.env` не читает:
для приложения также задайте переменные окружения. Файлы с локальными настройками
не отслеживаются Git; `database.properties` не используется приложением и исключён из JAR.
При изменении `DB_PORT` в Compose необходимо также задать соответствующий `DB_URL` для Java.
Изменение настроек Compose не меняет логин и пароль в уже созданной базе:
используйте реквизиты существующего PostgreSQL из КР 1.

## Возможности JavaFX

| Требование | Реализация |
|---|---|
| Две связанные сущности | `Client` → `ResourceRequest`, связь один ко многим |
| CRUD | Вкладки «Заявки» и «Клиенты», формы добавления/редактирования, подтверждение удаления |
| Связанные данные | Выбор клиента из ComboBox, сведения о клиенте в деталях заявки |
| Поиск | Название, описание и данные клиента без учёта регистра |
| Фильтры | Статус, тип, регион, клиент; фильтры и поиск применяются совместно |
| Сортировка | Щелчок по заголовку столбца; Shift + щелчок для нескольких столбцов |
| Статистика | 11 показателей; CPU/RAM/диск учитывают только `PROVISIONED` |
| Excel | Текущие отфильтрованные заявки в порядке таблицы, связанные клиенты и статистика выборки; путь через FileChooser |
| Обработка ошибок | Проверки полей, бизнес-правила, конфликты версий, ошибки БД и файлов в интерфейсе |
| FXML / CSS | Главное окно и обе формы в FXML; оформление в `app.css` |
| Отзывчивость | JDBC и экспорт выполняются в фоновом потоке; кнопки блокируются на время операции |

Типы ресурсов: `VIRTUAL_MACHINE` — виртуальная машина, `DATABASE` — управляемая БД,
`OBJECT_STORAGE` — объектное хранилище. Регионы: Москва, Санкт-Петербург, Казань.
Тип, регион, клиент и новый статус выбираются из списков с русскими названиями.
При выборе объектного хранилища поля CPU и RAM автоматически устанавливаются в ноль.
Дата создания определяется базой данных, пользователь её не вводит.
Экспорт не перезаписывает существующие файлы: выберите новое имя.
Вкладка статистики показывает всю загруженную базу; статистика в Excel относится к экспортируемой выборке.

## Бизнес-правила в Java

1. Имя клиента, компания и название заявки обязательны; длины ограничены схемой и сервисом.
2. Email имеет корректную базовую форму, приводится к нижнему регистру и уникален.
3. Клиент заявки должен существовать; ID должен быть положительным.
4. Тип ресурса и регион обязательны и выбираются из enum.
5. Диск — от 10 до 10000 ГБ.
6. Для VM/БД CPU — 1–64 ядра; RAM — не менее 2 ГБ на ядро, максимум 512 ГБ.
7. Для объектного хранилища CPU и RAM равны нулю.
8. Новая заявка всегда создаётся в статусе `NEW`.
9. Разрешены только переходы `NEW → APPROVED/REJECTED/CANCELLED`, `APPROVED → PROVISIONED/CANCELLED`.
10. Изменять параметры и клиента можно только у заявки `NEW`.
11. Удалять заявки `APPROVED` и `PROVISIONED` нельзя.
12. Нельзя удалить клиента, пока у него есть заявки.

Терминальные статусы: `PROVISIONED` (ресурс выделен), `REJECTED` (отказ), `CANCELLED` (отмена).
Повторное присвоение того же статуса также запрещено.
Описание необязательно, максимум 2000 символов. Изменение заявки проверяет `version`:
одновременное сохранение устаревшей версии отклоняется.
Проверки находятся в сервисах, поэтому действуют и при вызове вне консольного меню.
FK, UNIQUE, NOT NULL и CHECK дополнительно защищают данные в PostgreSQL.

## Устройство проекта

```text
src/main/java/ru/mirea/cloud/
  fx/           JavaFX Application, контроллеры, диалоги, фоновое выполнение
  model/        Client, ResourceRequest, enum
  service/      валидация, бизнес-правила, статистика, экспорт
  repository/   интерфейсы и JDBC-реализации (SQL только здесь)
  util/         настройки JDBC, запись Excel
  ui/           сохранённый консольный интерфейс КР 1
src/main/resources/
  ru/mirea/cloud/fx/  main.fxml, request-editor.fxml, client-editor.fxml, app.css
sql/            схема и исходные данные КР 1
```

`CloudApplication` создаёт зависимости и загружает FXML. `MainController` работает с
`ObservableList`, `FilteredList` и `SortedList`; `FxTasks` выполняет операции БД и файлов вне
JavaFX Application Thread и возвращает результат в UI. Контроллеры вызывают сервисы,
сервисы проверяют правила и вызывают JDBC-репозитории. REST API не используется.

Настройка Maven соответствует [официальной документации OpenJFX](https://openjfx.io/openjfx-docs/).

## Проверка

```powershell
mvn test
# Дополнительно, при работающей БД:
$env:RUN_DB_TESTS = 'true'
mvn test
Remove-Item Env:RUN_DB_TESTS
```

Интеграционные тесты создают отдельную временную схему PostgreSQL и удаляют только её.
